# Build and check the RC continuously

- Check the target branch's actual `tools/releasing/` scripts and parameters against current official guidance before running them. Confirm their required environment variables, invocation directories, and exact version files changed; these differ across maintenance branches, so old guide examples are not the script contract. Use the dedicated Flink worktree prepared under [workspace initialization](workspace.md), attached to its verified local or managed repository at a recorded maintenance-branch commit in detached HEAD state. Before each RC, confirm a clean worktree and the intended maintenance-branch SHA, with no conflicting branch/tag or previous RC action. Before a replacement RC, preserve the prior RC evidence, remove its build outputs, and switch the clean worktree to detached HEAD at the newly selected maintenance-branch SHA; never derive a new RC from the old RC commit by accident. Keep each candidate's artifacts and evidence in its own `rcN/` directory. After running, read back the branch, commit, japicmp baseline, and every changed version field before pushing.
- Bind one `x.y.z-rcN` to its signed tag, commit, signing fingerprint and KEYS, source and binary files, ASC/SHA512, Nexus staging repository, Python files under `python/`, website PR, and corresponding CI runs. Push the exact RC branch to the verified writable fork, trigger the target branch's wheel workflow, and download artifacts by their actual run ID, names, and paths; do not copy fixed filenames from the older bundled guide. Confirm each wheel traces to this RC commit and check the branch-specific platform matrix separately from any `apache-flink-libraries` universal wheel. Use a different build path only if its full required wheel matrix and provenance have been verified. Record each item's origin, hash, and upload result. Check Docker publishing readiness and access now; Docker images are finalized after the official release is available, not a required RC artifact.
- Apply the installed `verify-flink-release` skill's quality checks while producing each package, CI artifact, and website PR. Record creation-time evidence for the exact RC, including packaging, signing, license and notice coverage, provenance, build/runtime behavior, and version consistency. Investigate failures at their cause; do not continue with an apparently complete RC.
