# Vote and result

- Only after preflight passes, draft a `[VOTE]` with Jira release notes, the dist/dev RC, KEYS and fingerprint, Nexus staging, Git tag and commit, website PR, CI runs, deadline, and verification instructions. Confirm the current Flink and ASF vote window rules, normally at least 72 hours. Record the start and earliest valid close time. Save the original dev@ thread URL after sending.
- Read all replies, verification findings, and objections throughout the current vote. Investigate and answer each problem. A website PR wording or link fix may be made without cancelling an otherwise valid RC. For a substantive RC defect, explicitly cancel the vote in the old thread, delete or close the old Nexus staging repository, remove its dist/dev directory and RC tag as the current Flink guide requires, then fix, rebuild, and fully verify a numbered new RC. Clarify the old thread's status to prevent late votes being counted; do not infer prior public votes from an `rc4` tag.
- After the deadline, check binding status against the current PMC roster and the original message's **version and RC**, not the sender name alone. Record each +1/0/-1, binding status, rationale, and retraction; resolve ambiguous votes with the voter or release manager. Require at least three binding PMC +1 votes and more binding positive than negative votes under current ASF policy. Send a vote-closing message in the vote thread and a separate `[RESULT][VOTE]` with the count and voter evidence; save both links and lock the approved RC identity.
