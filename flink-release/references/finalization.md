# Finalization and public delivery

- Recheck that the approved RC's tag, commit, signatures, ATR revision, Nexus repository, and all artifacts to publish match exactly. Present the precise public or irreversible actions and destinations to the user. Once authorized, publish fully checked Python artifacts to PyPI, release the approved Nexus staging repository to Maven Central, have the release manager publish the ATR release to dist/release at `<atr>/finish/flink/<v>` with the subdirectory `flink-<v>` ([ATR integration](rc-creation.md#atr-integration); never commit to dist/release with SVN), create the official signed tag from the approved RC commit, push it to the verified authoritative Apache Flink Git remote, and mark the exact Jira version Released. After the Maven Central and PyPI releases, record both in ATR with `POST <atr>/api/distribution/record` (Bearer `$JWT`): `{"project":"flink","version":"<v>","platform":"MAVEN","distribution_owner_namespace":"org.apache.flink","distribution_package":"flink-core","distribution_version":"<v>","staging":false,"details":false}`, and the same with `"platform":"PYPI"` and `"distribution_package":"apache-flink"` without the namespace. Treat these as separate actions: read back PyPI files, Maven Central coordinates, the `dist/release/flink/flink-<v>/` listing against the approved revision's ATR path listing, `GET <atr>/api/distribution/list/flink/<v>`, the remote official tag and its peeled commit/signature, and Jira state before recording each PASS. A local tag or personal-fork tag alone does not complete publication. Do not treat a successful request or a same-version PyPI retry as proof of success.
- After official binary downloads work, update `apache/flink-docker`, build and publish `apache/flink` images, and verify the versioned Docker Hub image is pullable before announcing. Track the separate `docker-library/official-images` manifest PR for Docker's official `flink` image; that external merge is not under the Flink release manager's control. Record when the dist/release files first become available at downloads.apache.org. Before making the announcement blog public, check current ASF Infra distribution-cache guidance, wait its advised propagation interval (currently about one hour after availability), and recheck public downloads and mirrors. Check the actual publication date, download and release-note links, text, and merge conflicts. Follow the publication path confirmed during preparation: if the reviewed website PR includes generated `content/`, merge and deploy that result; if reviewers require a source-only PR, merge it, then build and separately push generated `content/` to `asf-site`. Do not perform an unreviewed duplicate rebuild. Read back the deployed site; neither a merged source PR nor a successful local build alone proves publication. Verify the public website and mirror URLs display this version.
