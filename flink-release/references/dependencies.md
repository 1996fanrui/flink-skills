# Internal dependency checks by stage

Read this file before starting each stage. Check only what that stage needs now. Install or configure tools the agent can safely provide, verify the result, and continue. Ask the requester for a specific credential, permission, signing action, or decision only when the agent cannot provide it. A missing dependency for a **later** stage is a non-blocking preparation note, not a reason to stop discovery or discussion. Do not expose a generic prerequisite list to the requester or put secrets in logs or release state.

| Stage | Needed for the current stage | Agent action | Human input only when needed |
| --- | --- | --- | --- |
| Workspace and resume | Writable `~/flink-release-workspaces/`, `git`, existing `workspace.md` and release states when present, local Flink repositories if discoverable | Read and validate saved locations; discover `flink`; create the fixed root and memory document on first use; use a local repository for discovery or initialize a managed one if absent; create a standalone clone per version, never a `git worktree` | Resolve only ambiguous repository choices or a workspace path/access problem the agent cannot fix |
| Discovery, before `[DISCUSS]` | Public Flink downloads, Git tags and maintenance branch (`git`), PR/CI metadata (`gh` or GitHub API), Jira issue/version data, dev@ archive access | Check tools and read access; install a missing CLI when feasible; gather and cross-check public facts and URLs | Supply evidence for a source the agent cannot access, or choose between genuinely conflicting release targets |
| `[DISCUSS]` | Proposal with source links; access to dev@flink.apache.org | Draft and review the message; use an authorized mail channel if available; record the posted thread URL | Confirm the release manager and send through an identity/channel the agent cannot use |
| Preparation after consensus | Target branch checkout and build matrix; Jira version/issue administration; GitHub PR access; GPG identity and KEYS; ATR account, token, SSH key, and per-version releases; Nexus, PyPI project quotas | Check each access independently, correct data the agent is authorized to change, and report precise blockers | Supply private signing identity or unavailable credentials; make community release decisions; grant missing rights |
| RC creation | The [RC creation checklist](rc-creation.md) and its permissions, credentials, and directories; the target branch's `tools/releasing/` scripts; the branch's release JDK, `git`, `gpg`, GNU tar/SHA512, `uv`, `rsync` and `ssh` for ATR, `curl`, `perl`, `jq` | Read the target branch's current script contract, check each credential row, run the checklist, and read back outputs | Type the GPG passphrase; perform web-login-only actions, including ATR setup; provide unavailable fork or publishing rights |
| RC verification | The installed `verify-flink-release` skill | Locate and invoke it for the exact RC; follow its own dependency checks. If absent, install it from the same skill source when available | Supply the verifier package only if the agent cannot access it; resolve inaccessible evidence or an RC quality decision |
| Vote and result | ATR token, dev@ archive access, current PMC roster, RC evidence and vote thread | Start the vote through ATR, watch replies, tally binding votes and record URLs | Cast each person's independent vote; resolve the vote in the ATR web UI |
| Finalization | Approved RC and explicit authorization; PyPI token/project maintainer rights, Nexus release, ATR publication to dist/release, signed Git tag and Apache remote write access, Jira version admin, Docker and website publishing rights, current `flink-web` build tool | Check each permission and build tool when its action becomes current; publish authorized objects and read back their public state | Authorize public or irreversible actions; provide credentials/signing identity the agent cannot access |
| Announcement and follow-up | Public mirror, Maven/PyPI/Docker/website availability; announcement mail; old-version cleanup and reporter access | Verify public links, draft authorized announcements, finish applicable cleanup | Announce and archive in the ATR web UI; supply unavailable reporter identity/rights |

Never print secret environment variable values, tokens, private keys, or Maven settings contents. Check a future stage early only to give the requester useful preparation notice; label that notice as non-blocking for the current stage.
