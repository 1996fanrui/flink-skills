# Flink skills project rules

This repository develops `flink-release` and `verify-flink-release` for Apache Flink main-project patch releases. The former gathers evidence before the initial dev@ discussion and follows the release through publication and cleanup; the latter verifies a specific release candidate independently and is also used by the release manager before a vote. Neither skill publishes a new major or minor release.

Follow [SKILL_DESIGN.md](SKILL_DESIGN.md) when creating or changing a skill. A skill run investigates the **current target release or RC**, not the previous ten releases again. When a later release exposes a new failure, revise the relevant skill and its checks.

Write skill instructions, supporting references, and the repository README in English. Each installable skill must state its own community-facing language rule in `SKILL.md`; a downloaded skill cannot rely on this project's rules. Respond to each requester in their preferred language. Keep the two skills installable from their own directories; runtime instructions must not depend on intermediate research files, the author's conversation, or any maintainer-specific project or filesystem layout.

At runtime, discover the next patch version from official releases, tags, the maintenance branch, and Jira. Before a discussion email, gather accessible evidence and give the requester checked review links and a draft. Put the workflow directly in `flink-release/SKILL.md`; keep simple, short stages there and link only substantial stage details to references. Avoid a parallel stages index. Keep stage-specific tool and permission checks in the internal dependency references: resolve what the agent safely can, request only specific human input needed now, and label future needs as non-blocking. Apply the same quality standard while creating and verifying an RC. Bind every check and artifact to the exact version, RC, and commit; never transfer a failed RC's checks or votes to a new candidate. A human PMC member remains responsible for independent votes, release decisions, and use of their private signing identity.
